WEB DEV

Development of an e-learning website with the tagline “Learn. Build. Share.”

15 Nov 2026 • By Ekuivalen
Join The Newsletter for Tech & Builders
1,200+ Readers
Ekuivalen

Learning information technology on your own often feels fragmented. Typically, a learner has to search for materials on one website, build a portfolio of achievements on another platform, and then switch to yet another site when they want to share the insights they’ve gained. This fragmentation was the starting point for the design of TUT.EDU (Tech Up Training & Education).

With the tagline “Learn. Build. Share.,” TUT.EDU is designed as a web-based IT education ecosystem that brings together interactive learning spaces, a creator studio, and a public portfolio within a single integrated platform. All classes on the platform are accessible for free, with no payment, transaction, or checkout process required.

Why Build a “Learn. Build. Share.” Cycle?

Instead of functioning as a one-way course website, TUT.EDU turns learning into a self-reinforcing closed loop: users absorb technical concepts (Learn), solidify their knowledge by building their own classes (Build), and showcase their track record openly (Share).

To keep the architecture clean without unnecessary account switching, TUT.EDU uses only two actual account roles: user and admin. Meanwhile, Learner, Creator, and Public Profile act as usage modes within the same account—meaning any registered user can seamlessly start creating courses without signing up again or managing a second profile.

A unified learning ecosystem works best when studying, building real material, and proving your skills happen in one continuous flow rather than across disconnected tools.

Three Core Modes Under One Account

In total, the system specification maps out 40 functional capabilities to deliver an end-to-end experience. On the user side, these features are organized into three primary workspaces:

  • Learning Workspace (Learn): Explore both official curricula and community-made classes in one catalog with keyword search and filters by IT category, difficulty level (Beginner, Intermediate, Advanced), star rating, and course source. One-click enrollment sends classes straight to My Learning, where a modular viewer combines text articles, embedded YouTube videos, infographics, syntax-highlighted code blocks, a Mark as Complete tracker, and instant-scored multiple-choice quizzes.
  • Creator Studio (Build): Structure a syllabus into chapters and lessons, insert text, YouTube links, images, code snippets, and custom quizzes. Creators can save unfinished courses as drafts and submit them for Admin review once all content requirements are complete.
  • Public Portfolio (Share): Every user gets a unique URL at /profile/{username} showcasing their bio, learning milestones, published classes, digital certificates, and external links to GitHub, LinkedIn, or personal websites—backed by privacy toggles to show or hide learning progress and enrolled classes at any time.

Admin Governance: Official vs. Community Courses

Allowing users to publish their own courses requires consistent quality control. Through an Executive Analytics Dashboard, Admins monitor total users, published courses, and pending review queues while maintaining two distinct course tracks:

  • TUT.EDU Official Class: Standardized curricula authored directly by Admins via the Official Class Studio, published immediately without a review queue, and labeled with the TUT.EDU Official badge.
  • User-Created Class: Community submissions reviewed at the Curated Class Review Desk. Approved classes go live with creator attribution, while rejected submissions receive structured revision feedback so authors can improve and resubmit them.

Admins also manage IT categories, control account status (active or blocked), and moderate discussions by hiding comments that violate community guidelines. Engagement rules stay strictly validated: optional 1–5 star ratings are limited to one updatable rating per completed course, while enrolled learners can freely post comments.

Database Architecture: 17 Relational Tables

Behind every workflow sits a relational schema of 17 core tables designed as the blueprint for migrations, models, relationships, and the ERD in Laravel 13: 

// Core & Content
            users, categories, courses, chapters, lessons

            // Learning & Assessments
            enrollments, progress, quizzes, quiz_questions, quiz_answers, quiz_attempts

            // Community, Portfolio, Curation & AI
            ratings, comments, certificates, portfolio_links, course_submissions, ai_conversations

To keep server storage lightweight, the video_url column in lessons stores YouTube links for embedding instead of hosting raw video files directly on the server.

Integrating TUT AI Securely

One of the key highlights of the platform is TUT AI, an AI-powered IT learning assistant that helps learners grasp programming concepts, decode error messages, and get debugging guidance.

When a user submits a question, the Laravel backend forwards it to an external AI service using an API key stored strictly inside the server’s .env configuration—never exposed to the frontend. Responses can be saved to the ai_conversations table when chat history is enabled, and if an API request fails, the system displays a clear retry message without crashing the app or leaking sensitive details.

By mapping all 40 features, system flowcharts, data requirements, and all 17 database tables before writing production code, building TUT.EDU in Laravel 13 stays structured from day one—turning Learn, Build, Share from a concept into a clean, ready-to-build web ecosystem.
